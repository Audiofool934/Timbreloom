# Timbreloom

Timbreloom 是一个只监听 `127.0.0.1` 的本地声音创作工具。
它把保存的音色连续织入新的长文本中。
它使用 Qwen3-TTS 0.6B Base 和 Apple MLX，在 Apple Silicon Mac 上根据短参考录音生成新的语音。

## 已部署能力

- 上传 WAV、M4A、MP3、FLAC、AAC、CAF、OGG 或 WebM 参考录音。
- 把参考录音和准确转写保存为可重复使用的本地音色。
- 输入日常使用范围内的任意长文本。
- 按语义边界组合多句话，而不是一句一段。
- 每个生成分段固定使用最多 1,024 个音频 token。
- 分段前执行逐字符完整性校验，确保没有文本被遗漏或重复。
- 每个分段失败时自动重试一次，仍失败则停止整个任务。
- 在页面上显示当前阶段、分段数量、完成比例和当前文本。
- 使用恒定内存顺序拼接分段，在本地提供一个完整 WAV。
- 页面刷新后可以恢复仍在运行的任务进度。
- 当前采样温度设置为 `1.0`，用于增加生成变化和表现力。

## 启动

项目根目录是 `~/Projects/Timbreloom`。
代码、模型权重、Python 环境和本地数据都位于这个目录中。

首次安装或本地模型缺失时：

```bash
./setup.sh
```

启动网页：

```bash
./start.sh
```

然后打开 `http://127.0.0.1:7865`。

## 保存音色

1. 选择一段 5 至 15 秒的清晰录音。
2. 填写与录音逐字一致的参考文字。
3. 输入音色名称并点击“保存音色”。
4. 之后可以从“音色来源”下拉框直接选择它。

音色保存在 `data/voices/`。
删除音色只会删除对应参考录音和文字，不会删除已经生成的 WAV。

默认模型权重位于 `models/Qwen3-TTS-12Hz-0.6B-Base-bf16/`。
启动时直接从项目内加载，不依赖全局 Hugging Face 缓存。

## 长文本分段

系统先按句号、问号、感叹号和段落寻找语义边界。
它会尽量把多句话组合到同一段中，避免一句一段导致语气不连贯。
如果单句话过长，才会继续在逗号、分号、冒号、空格或安全字符位置分开。
每段的保守估算上限为 880 个音频 token，模型硬上限仍为 1,024 个音频 token。
当前语速估算通常对应约 50 至 70 秒一段。

所谓持续生成是通过逐段处理实现的。
实际总长度仍受运行时间、磁盘空间和 200,000 字符安全上限约束。

## 语气写法

当前 Base 声音克隆模型不支持 `instruct` 情绪指令，也没有 `[开心]`、`[laugh]` 或 SSML `<prosody>` 这类隐藏语气标签。
这些标签如果直接写进目标文本，可能会被模型念出来。

可以使用正常文字和自然标点给模型提供语义提示：

- `啊……我还没想好。` 表示犹豫或轻微延长。
- `啊？！真的成功了！` 表示惊讶和强调。
- `啊？你刚才说什么？` 表示疑问和上扬。
- `哈哈……原来是这样。` 或 `唉……算了。` 使用可直接朗读的拟声词。

省略号、问号、感叹号和 `～` 只能引导模型，不保证具体音高、情绪或持续时长。
如果需要让一个字精确持续 1 至 2 秒，需要另行实现局部音频拉伸和拼接，而不是添加文本标签。

## 隐私与边界

服务只绑定本机地址，不应改成公网监听地址。
参考录音、音色和生成结果不会上传到第三方服务。
请只克隆本人或已经获得明确授权的声音。
对外发布生成内容时应标记为 AI 合成。
